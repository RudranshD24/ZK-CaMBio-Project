## Face source decision (the agent must resolve this in Phase 1, not guess)
CelebA's Kaggle mirror has **no identity labels**, and this project needs "which images are the same person" for genuine pairs.
1. Inspect `dataset/facial_dataset/`. If it contains a face set **with identity labels** (e.g., UMDFaces: identity/subject id per image, >= 10 images per identity), use it as the face source.
2. Otherwise, use CelebA **only if** `dataset/archive/identity_CelebA.txt` exists (format: `000001.jpg 2880`). It is in the "Anno" section of the official CelebA page (mmlab.ie.cuhk.edu.hk/projects/CelebA.html). If missing, **STOP and ask the user** to add it. Do not fabricate identities, do not cluster faces to invent labels without asking.
3. Record the outcome as decision D-005 in DECISIONS.md.
CelebA/UMDFaces are research-only datasets: keep out of git, do not redistribute, cite them.

## Fingerprint (FVC2004)
- Use **DB1_A, DB2_A, DB3_A** (real sensors): 3 x 100 fingers x 8 impressions = 300 fingers. `DB4_A` is synthetic (SFinGe): optional extra experiment only. `*_B` sets (10 fingers each) are not used for the main protocol; they may serve as a small dev set.
- Filename `F_I.tif`: F = finger 1-100, I = impression 1-8. Finger IDs repeat across DBs, so the unique finger key is `(DB, F)`, e.g. `DB2_A:17`.
- Ignore the `index_*.MFA/MFR` files (FVC competition match lists). Ignore any SFinGe installer.

## Selection & pairing
- Face identities: keep those with **>= 10 images** (CelebA averages ~20 per identity). Sort ids, shuffle with seed 42, take 300.
- Shuffle the 300 `(DB, finger)` keys with seed 42. Pair by index -> virtual subjects `VS_0001..VS_0300`.

## Split (subject-disjoint, saved manifest)
| Set | Virtual subjects | Use |
|---|---|---|
| train | 180 | fingerprint encoder training, fusion weight tuning |
| test | 120 | ALL reported metrics |
Manifest: `data/processed/split_manifest.json` (outside `dataset/`; git-ignored except the manifest hash in DECISIONS.md). Pairing and split must be generated by one script and reproducible from seed 42. Stratify so each fingerprint DB appears in both train and test.

## Per-subject protocol
- Fingerprint: impressions 1-5 enroll, 6-8 probe.
- Face: 10+ images -> 5 enroll, 3 probe, chosen by seed with no overlap; record filenames.
- Genuine = probe of s vs template of s. Impostor = probe of s vs template of every s' != s.
- Report per fingerprint DB and pooled.

## Preprocessing
- Face: CelebA images are already aligned (178x218). Use `list_bbox_celeba.csv` / landmarks if helpful, otherwise resize/center-crop to the encoder size (e.g., 160x160 for facenet-pytorch). Run a face detector only if the encoder needs it.
- Fingerprint: grayscale, intensity normalization, CLAHE, crop to foreground, resize (e.g., 224x224 or 96x96). FVC images differ in size per DB (check in inspection).

## First script (Phase 1, run before anything else)
`experiments/00_inspect_data.py` prints, and saves to `results/data_inspection.txt`:
- tree depth 2 of each dataset root, file counts by extension
- `facial_dataset`: what it is, whether identity labels exist, images-per-identity histogram
- CelebA: whether `identity_CelebA.txt` exists, csv headers + row counts
- FVC: images per DB folder, image sizes per DB, confirm 100 fingers x 8 impressions in each `_A`
It must not print more than a few sample names per folder.
